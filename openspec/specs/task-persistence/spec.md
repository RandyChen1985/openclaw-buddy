# 规格：任务持久化 (task-persistence)

## 需求说明
系统必须能够持久化存储所有耗时任务的状态，以便在系统重启后能够恢复任务上下文或进行审计。

## 业务逻辑
1. **表结构**：在 SQLite 中维护 `tasks` 表。
2. **任务初始化**：API 收到请求后，立即在表中插入一条 `Pending` 或 `Running` 状态的记录，并返回其 `ID`。
3. **结果更新**：任务协程结束时（无论成功、失败或超时），必须回写 `result`, `error` 和 `end_time`。
4. **中断处理**：系统启动时，扫描所有处于 `Running` 状态的任务，将其状态统一更新为 `Interrupted`（已中断）。

## 验收标准
- [ ] 数据库中存在 `tasks` 表且包含定义的所有字段。
- [ ] 调用异步 API 后，数据库中能实时查看到该任务记录。
- [ ] 强制关闭 Buddy 并重启后，原有的 `Running` 任务变为 `Interrupted`。
