# 规格：任务并发控制 (task-concurrency-control)

## 需求说明
系统应防止对同一个模块执行冲突的耗时任务，以保护配置文件的完整性和系统稳定性。

## 业务逻辑
1. **模块划分**：分为 `gateway`, `bots`, `models`, `plugins`, `skills` 等模块。
2. **互斥规则**：
   - 同一个模块在同一时间只能有一个 `Running` 状态的任务。
   - 若用户触发新任务，而所属模块已有活跃任务，API 应返回 `409 Conflict`。
3. **强制释放**：任务超时（120s）后，系统必须强制释放该模块的锁定状态。

## 验收标准
- [ ] 连续点击两次“网关重启”，第二次请求应被拒绝并提示冲突。
- [ ] 不同机器人的添加操作（属于 `bots` 模块的不同实例）在当前版本中建议也进行全局锁定以确保安全。
- [ ] 任务完成后，后续任务能够立即成功启动。
